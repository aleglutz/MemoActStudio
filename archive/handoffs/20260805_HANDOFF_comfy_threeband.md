# Задание: интерактивная нода-стек для ComfyUI («три полосы 9:16»)

**Проект:** MemoActs 2026 · рил «Legends of Surrender» для Museum Berlin-Karlshorst
**Кому:** агенту с рабочим ComfyUI MCP
**Статус:** связка нод выбрана по документации, но **не проверена в работающем ComfyUI** — это и есть задача

---

## 1. Зачем

Основной визуальный приём ролика — вертикальный кадр 1080×1920, собранный из двух или трёх горизонтальных архивных кадров, уложенных друг на друга. Приём повторяется примерно в десяти шотах из двадцати одного, и дальше его будут применять студенты лаборатории в восьми собственных работах.

Нужен **один воспроизводимый инструмент с ручной подгонкой кропа мышкой**, а не набор консольных команд: студенты не программисты, а точку кропа приходится подбирать под каждый кадр индивидуально.

Референс геометрии и рабочий эталон результата — `stitch.sh` в этой же папке (ffmpeg). Он уже даёт правильные кадры; нода должна повторить его результат, но интерактивно.

---

## 2. Геометрия (жёсткая)

Кадр **1080×1920**.

| Раскладка | Полосы | Швы | Проверка |
|---|---|---|---|
| Две полосы | 957 + 957 | 6 px между | 957·2 + 6 = 1920 |
| Три полосы | 636 + 636 + 636 | 6 px ×2 | 636·3 + 6·2 = 1920 |

Шов — чёрный. Полей и размытой заливки быть не должно: исходник масштабируется до заполнения полосы и обрезается.

---

## 3. Предлагаемая связка (проверить и собрать)

```
LoadImage ×3            (или VHS_LoadVideo для хроники)
  → Olm DragCrop ×3     интерактивная рамка; пропорция 1080:636, привязка 8 px
  → ImageScale ×3       1080×636, lanczos
EmptyImage 1080×6 color 0                        ← шов
  → ImageConcatMulti    inputcount 5, direction "down", match_image_size FALSE
                        порядок входов: A, шов, B, шов, C
  = 1080×1920
```

Зависимости:

* **ComfyUI-Olm-DragCrop** — https://github.com/o-l-l-i/ComfyUI-Olm-DragCrop
  Интерактивная рамка прямо на превью ноды, ручки по углам и краям, числовые поля Left/Right/Top/Bottom синхронизированы с рамкой, фиксация пропорции, привязка к сетке 2–64 px.
* **ComfyUI-KJNodes** — https://github.com/kijai/ComfyUI-KJNodes
  `ImageConcatMulti`: `inputcount`, `direction` (`up`/`down`/`left`/`right`), `match_image_size`.

Для двухполосного варианта — то же самое, пропорция 1080:957, `inputcount 3`.

---

## 4. Что именно проверить

1. **`match_image_size` должен быть FALSE.** При TRUE все входы приводятся к размеру первого, и швы 1080×6 растянет до 1080×636 — кадр развалится. Подтвердить поведение опытом.
2. **Ось кропа зависит от пропорций исходника** — самая неочевидная часть. Если исходник шире полосы, масштабирование идёт по высоте и обрезка получается **горизонтальной**; если уже — по ширине и обрезка **вертикальная**. В нашем наборе есть оба случая (таблица в §6). Убедиться, что DragCrop корректно отрабатывает обе ситуации и что рамка с фиксированной пропорцией не выходит за границы изображения.
3. **Батч / видео.** IMAGE в ComfyUI это `[B,H,W,C]`. Проверить, что DragCrop применяет одну рамку ко всему батчу кадров, загруженному через VHS_LoadVideo, а не только к первому.
4. **Швы на видео — известное узкое место.** `EmptyImage` отдаёт батч фиксированной длины, хроника приходит батчем из N кадров; при расхождении длины конкатенация упадёт. Решить одним из способов и зафиксировать в шаблоне:
   * подать `batch_size` шва от числа кадров;
   * либо собирать видео без швов, добавляя разделители на монтаже;
   * либо заменить `EmptyImage` на ноду, повторяющую кадр по батчу.
5. **Сверка с эталоном.** Прогнать связку на трёх ассетах из §6 и сравнить с `composites/S14_three-band.png`, собранным ffmpeg. Расхождение по геометрии — недопустимо, по интерполяции — приемлемо.

### Перевод `c` в пиксели

При вертикальной обрезке исходник масштабируется по ширине до 1080. Высота прямоугольника в координатах оригинала:

```
rect_h = band * w / 1080
top    = c * (h - rect_h)
```

Например `GIoS_Wehrmacht_Signed_Ru.jpg`, band 636, c 0.11: `rect_h = 636·1860/1080 = 1095`, `top = 0.11·(2560−1095) = 161 px`.

При горизонтальной обрезке симметрично: `rect_w = 1080 * h / band`, `left = c * (w − rect_w)`.
